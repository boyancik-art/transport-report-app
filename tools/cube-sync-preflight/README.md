# Cube bridge — безпечний preflight 1.0

Це перший, діагностичний етап, а не активований production sync.
**Не виконує HTTP-запитів, не імпортує й не видаляє дані, не змінює тарифи,
не створює розклад та не запускає TestFlight.**

## Одна дія на Windows-ПК

Розпакуйте пакет у звичайну локальну папку та запустіть `Run-Preflight.cmd`
під своїм звичайним Windows-користувачем, у якого працює Excel і доступ до Куба.
Права Administrator Windows не потрібні. Наприкінці відкриється папка зі звітом
`Cube-preflight-report.zip` — надайте саме цей ZIP для наступного етапу.
Не надсилайте книгу чи `payload.dpapi`.

Потрібні Windows PowerShell 5.1 і встановлений настільний Microsoft Excel.
Початковий ліміт Refresh — 20 хвилин. Якщо корпоративна політика забороняє
запуск непідписаних скриптів, потрібне підписання/дозвіл ІТ; пакет не обходить
Group Policy. Не вводьте паролі у скрипт чи config.json.

## Що відбувається

1. Самотестування дат, чисел, ID, періоду і виявлення колізій ключів.
2. Окремий Excel COM-процес з вимкненими макросами, без приєднання до вашого Excel.
3. `База.xlsx` відкривається read-only, запускається `RefreshAll`, очікування
   `CalculateUntilAsyncQueriesDone`, станів підключень і завершення розрахунків.
4. Додаткова перевірка RefreshDate у QueryTable/PivotCache для підключень.
   Непідтримувані/непідтверджені підключення не вважаються успішними.
5. Перевірка заголовків, типів, ID, кількості рядків за кожну дату
   01.08.2026–03.09.2026. Невалідні рядки не пропускаються мовчки.
6. Формування сумісних полів JSON у пам'яті; payload зберігається лише локально
   в DPAPI-зашифрованому вигляді для цього Windows-користувача.
7. Закриття Excel без збереження книги. При зависанні завершується тільки
   власний процес, перевірений за PID і часом створення. Чужі Excel не закриваються.

Результати: `%LOCALAPPDATA%\TransportReportCubeBridge\<run-id>\`.
`last-run.txt` вказує на останній звіт. Звіт містить лише технічну діагностику,
назви підключень/полів, підсумкові лічильники й дати; не містить паролів,
connection strings, токенів або списку клієнтів/накладних.

## Чому preflight не активує синхронізацію

Чинний deployed endpoint `import-cube-json` перед імпортом видаляє
`source_documents` і `route_points` за період. Його використовувати для
постійної синхронізації не можна.

Ключ `source_key` включає індекс рядка. Він змінюється при перестановці Excel-рядків.
Перевірка бази 03.09.2026 виявила 30 груп колізій кандидата
`date + route + group + op + sale + address + customer + employee + business`.
Є як однакові, так і різні суми в таких групах. Поле `*№` у перевірених прикладах
порожнє. Автоматичне видалення «дублів» або вибір останнього рядка тут неприпустимі.

Спочатку звіряємо свіжу книгу: потрібний стабільний ID вихідного рядка Куба
або погоджене правило його ідентифікації. Додавання суми/ваги в ключ не вирішує
проблему — тоді виправлення суми створюватиме новий документ.

Мінімальна/максимальна дата, час модифікації XLSX чи просто завершення Refresh
НЕ доводять повноту вибірки Куба. Дні без рядків наведені окремо: це можуть бути
як порожні операційні дні, так і обмеження запиту. Для clean потрібне підтвердження
меж/повноти запиту з джерела та актуальності його результату.

## Наступний етап після звіту

Підготувати й перевірити атомарний incremental backend, RLS/admin-доступ,
чергу запитів і локальний worker; лише потім підключати розклад та кнопку.
Технічний контракт і критерії приймання — у `SYNC-CONTRACT.md`.
**У цьому пакеті DAILY/FORCE/CLEAN не активовані.**
